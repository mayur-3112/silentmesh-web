Security

last reviewed 3 October 2026

SilentMesh runs on a network that controls physical equipment, so its first job is to be harmless. This page states what it guarantees, how each guarantee is tested, and what is not done yet.

Report a vulnerability

Email founder@silentmesh.me with "security" in the subject. We will confirm receipt, keep you informed until it is fixed, and credit you if you want. Please give us a reasonable time to fix before publishing. Machine-readable contact: /.well-known/security.txt.

Guarantees, and the test behind each

GuaranteeHow it is enforcedTested by
never blocksThe kernel program has two outcomes, pass or hand to a decoy. No drop path exists in the code.20,000 random packets per kernel returned byte for byte, new seed each run
fails openThe kernel releases the program when the daemon exits for any reason; a frozen daemon loses a kernel lease within about 9 seconds.Chaos tests on kernels 6.6 to 7.2 on every change: kill, terminate, freeze, hung and dead decoys, kill switch
never initiatesDecoys only answer connections addressed to them.A pilot pass criterion, checked against the plant's own switch log
can always be disarmedThe daemon refuses to arm if the console, which carries the kill switch, cannot start.Enforced in the startup path; the kill switch itself is exercised by the chaos suite
does not steal a real portIn a redirecting mode it refuses to arm if a decoy port is already in use, and re-checks about once a minute.Preflight tests
survives hostile inputEvery parser an attacker can reach is fuzzed.5,937 structured fuzz cases across seven decoys, zero crashes; 11 Go fuzz targets; the fuzz step fails if no target ran
keeps data on siteEvery alert destination is off until configured. The console listens on 127.0.0.1 by default.Shipped defaults, documented in the configuration reference

How changes ship

  • Nothing reaches the main branch without passing the full gate: build, vet, race detector, decoy tests, the kernel chaos suite on five kernels, fuzzing, a quality ratchet that forbids any metric from getting worse, and a check that blocks banned overclaims in shipped text.
  • A nightly run repeats the fuzzing for longer, plus soak and longevity tests.
  • An independent penetration test against a live deployment found no remote code execution, no authentication bypass and no unauthorised change to process state. Its two findings were fixed during the engagement.

Not done yet

  • Decoys run as separate supervised processes but do not yet drop root privileges. This is the next hardening step.
  • The console serves plain HTTP unless TLS is configured. Keep it on a management network or enable TLS.
  • Incident records carry a SHA-256 to detect edits after export; the event store itself is not append-only and nothing is signed.
  • IPv4 only. IPv6 passes through untouched and is not intercepted.
  • No third-party security audit or safety certification.
